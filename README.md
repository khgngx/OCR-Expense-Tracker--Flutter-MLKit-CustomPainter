# OCR Expense Tracker

Flutter app that scans receipts with OCR, parses them with a regex heuristic engine, lets you review/edit, stores them in SQLite, and visualizes spending with pure `CustomPainter` charts and a "daily bill stack".

Runs on **iOS / Android** (ML Kit, fully offline) and on the **web / PWA** (Tesseract.js in the browser).

**Live demo:** `https://khgngx.github.io/OCR-Expense-Tracker--Flutter-MLKit-CustomPainter/` (after enabling GitHub Pages, see below)

## Try the web demo

- On a wide screen you get the **desktop layout** (side rail, charts side by side). The toggle (bottom of the rail, or top-right in phone view) switches to a **simulated phone frame**.
- No receipt at hand? On the empty list tap **Load demo data** (charts and bill stack fill up), and in **Scan → Samples** pick a bundled sample receipt to run real OCR + parsing.
- **Scan** also works with your webcam (allow camera access) or **Import** of any receipt photo.
- On a phone, open the link and use *Add to Home Screen* to install it as a fullscreen PWA.

### OCR differs by platform

| | Engine | Notes |
|---|---|---|
| iOS / Android | Google ML Kit | on-device, offline |
| Web | Tesseract.js (WebAssembly) | runs in the browser, the image is never uploaded; the library and Vietnamese/English language data are downloaded from a CDN on first use; less accurate than ML Kit |

Sample receipts in `assets/sample_receipts/` are **fake demo data** generated by `tool/generate_sample_receipts.py`.

## Architecture

Feature-first, 3 layers (Presentation / Domain / Data):

- `lib/core` – theme, colors, formatters, responsive layout (`layout/`), platform switch (`platform/`)
- `lib/domain` – `Receipt` model, use cases (parse, save, daily summary, weekly spending, demo seed)
- `lib/data` – sqflite database + DAO, `ReceiptRepository`, thumbnail storage
- `lib/features/*` – `camera_scan`, `receipt_review`, `transaction_list`, `charts`, `bill_stack`

Features read data only through `ReceiptRepository`. Dependencies are wired by hand in `lib/main.dart` and exposed via `AppScope`. Platform-specific pieces (OCR engine, thumbnail storage, database factory) are chosen at compile time in `lib/core/platform/`.

## Run

```bash
flutter pub get
flutter test
flutter run -d chrome        # web
flutter run                  # iOS/Android device (needs a camera for live scan)
```

Requirements: Android minSdk 24, iOS 15.5+ (ML Kit).

## Deploy the web demo (GitHub Pages)

1. Repo **Settings → Pages → Build and deployment → Source: GitHub Actions**.
2. Push to `main`; `.github/workflows/deploy_web.yml` analyzes, tests, builds and publishes.

The web database needs `web/sqlite3.wasm` (committed). To regenerate it: `dart run sqflite_common_ffi_web:setup` (then delete the generated `sqflite_sw.js`, the app uses the no-worker factory).

Regenerate icons / sample receipts with `python3 tool/generate_web_icons.py` and `python3 tool/generate_sample_receipts.py` (Pillow).
